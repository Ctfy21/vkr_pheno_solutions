# Сайт стартап-проекта PhenoPlant

Статическая страница без сборки: `index.html`, `styles.css`, `main.js`, изображения в `img/` и промо-ролик в `media/`.

## Перед публикацией

1. Контакты в разделе «Контакты» (помечены пунктиром): e-mail, телефон, Telegram.
2. При необходимости поправьте тарифы и состав команды.

Логотип Фонда содействия инновациям (`img/fasie-logo.webp`) и текст о поддержке Фонда стоят в полосе под первым экраном и в подвале; по условиям программы они должны оставаться на главной странице.

## Публикация на GitHub Pages

1. В репозитории: Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. После слияния в `main` workflow `.github/workflows/pages.yml` опубликует сайт по адресу
   `https://ctfy21.github.io/vkr_pheno_solutions/`.
3. Свой домен: добавьте файл `site/CNAME` с именем домена и настройте DNS по инструкции GitHub Pages.

## Публикация на своём сервере

Сайт работает на https://phenoplant.ru/. Workflow `.github/workflows/site-server.yml` после каждого изменения `site/` в `main` копирует сайт на сервер по SSH (rsync), а nginx отдаёт его по HTTPS с сертификатом Let's Encrypt. Скрипт `deploy/site-server/setup.sh` перед загрузкой:

- ставит nginx, rsync и certbot, если их нет;
- получает сертификат для домена и для `www.`, если запись `www` указывает на тот же сервер (сертификат продлевается сам, таймером certbot, и nginx после продления перечитывает его);
- пишет блок сервера PhenoPlant: порт 80 переадресует на `https://phenoplant.ru`, `www` тоже ведёт на основной адрес; другие сайты nginx на сервере не трогает.

Пока сертификата нет (домен ещё не смотрит на сервер или закрыт порт 80), сайт открывается по `http://` на адресе сервера, а в журнале запуска появляется предупреждение.

Один раз настроить:

1. На сервере добавить открытый ключ деплоя в `~/.ssh/authorized_keys` пользователя, под которым идёт загрузка (по умолчанию `root`).
2. В репозитории: Settings → Secrets and variables → Actions → Secrets → New repository secret:
   - `SSH_HOST` — адрес сервера;
   - `SSH_PRIVATE_KEY` — закрытый ключ деплоя целиком, вместе со строками `-----BEGIN…` и `-----END…`.
3. Необязательно, во вкладке Variables: `SITE_DOMAIN` (по умолчанию `phenoplant.ru`), `CERT_EMAIL` (адрес для писем Let's Encrypt о сроке сертификата), `SSH_USER` (по умолчанию `root`), `SITE_DIR` (по умолчанию `/var/www/phenoplant`).
4. Actions → «Site to server» → Run workflow, чтобы залить сайт сразу, не дожидаясь следующего изменения.

В файрволе сервера и у провайдера должны быть открыты порты 80 и 443.

## Промо-ролик

`media/phenoplant-promo.mp4` (H.264) и `media/phenoplant-promo.webm` (VP9, для браузеров без H.264), 720×720, 21,5 с, постер `media/phenoplant-promo.jpg`.
Ролик собран на реальных снимках сои от 12.10.2026: маска, масштаб по линейке, высота и площадь листьев посчитаны кодом платформы (`backend/app/analyze.py`), цифры совпадают с отчётом. Музыка написана для ролика, сторонних записей в нём нет.
В шапке ролик играет без звука; кнопки позволяют остановить его и включить звук. При настройке «уменьшить движение» ролик не запускается сам.

## Изображения

Экраны и кадры реального опыта с соей (съёмка 12.10.2026, пять растений, варианты 3 и 4):

- `pipeline.webp` — этапы обработки снимка 4_O2_4: маска, метки линейки, верх и край горшка, итог;
- `statistics.webp` — вкладка «Статистика»;
- `upload.webp`, `run.webp`, `measure.webp`, `export.webp` — загрузка, выбор метода, измерения снимка, экспорт;
- `report-pdf.webp` — страницы PDF-отчёта.

## Оформление

Шрифт — Onest (Google Fonts): он рисовался прежде всего для русского языка, поэтому кириллица в заголовках и цифрах выглядит ровно. Мелких подписей нет: самый мелкий текст на странице — 14 px.

Композиция первого экрана (наклонная карточка с роликом, кнопки звука, карточка с призывом) и чередование цветных разделов взяты со страницы проекта [brag](https://github.com/latent-spaces/brag) (MIT, © 2026 Shunit Haviv Hakimi); текст лицензии приведён в начале `styles.css`.
